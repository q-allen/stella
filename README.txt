STELLA BOOTSTRAP MULTIPAGE PROTOTYPE

Extract the ZIP and open index.html. Internet access is needed for Bootstrap CSS from jsDelivr. Custom CSS provides basic layout if the CDN is unavailable. No build tools or React required.

Open page-directory.html to browse every screen. Each screen has a separate HTML file. Shared assets/styles.css and assets/app.js keep the layouts consistent. assets/stella.png is the previously generated mascot.

This is a front-end prototype, NOT a production system. Login is an explicit role picker; no real authentication, authorization, email delivery, file upload or database. Never enter real student or confidential school data. There are no student accounts, grades or submissions.

Records start empty. To test: choose Admin, add a resource and a digital material. Switch to Teacher, create a borrowing request. Switch to Principal, approve it. Switch to Admin, open the request and issue materials. View Loan Details to record a partial or full return. Teacher can record classroom use independently of downloading a file. No synthetic school data is included.

Session storage saves demo metadata in the current browser tab when supported. File content is not stored; only the selected filename is retained. Material Details lets you reselect a local file and download it. If storage is blocked under file://, use a local static server. Refresh persistence is not guaranteed in restricted browsers.

Reports reflect entered records; Print uses the browser print dialog. Inventory availability is checked on issue; partial returns are supported. Prototype UI role selection is not security. Optional password recovery and reset are demonstration screens only.

Scope limitations: a request currently contains one resource line; multiple-item requests require further development. Quantity/condition inventory is aggregated, not serialized per item. No independent wing/eye/cape rig in this prototype: landing mascot uses the complete PNG with gentle hover. No notifications, backups, auditing security or real upload preview service. All forms and routes should be reviewed before connecting a backend.
